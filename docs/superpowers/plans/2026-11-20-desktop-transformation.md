# Zlog 桌面端改造计划（含首次使用引导）

> 执行方式：按阶段拆分、逐批交付。本文档中的「第一批」是本轮实际落地范围，其余阶段保留为路线图，不一次性铺开。

**目标：** 在保留 Web 端不变的前提下，把 Electron 外壳从「网页容器」升级为符合桌面应用习惯的写作工具，并用渐进式引导降低首次配置成本。

**架构：** 单一主窗口承载阅读与写作两种工作模式；菜单、工具栏、命令面板共享同一份命令注册表；后台管理先做两栏，宽屏再演进为三栏；同步/离线状态作为一等公民贯穿首启、仪表盘和编辑流程。

**技术栈：** Electron 37、Next.js 16 App Router、React 19、TypeScript、libsql/Turso embedded replica、Vitest、Playwright Electron。

## 全局约束

- Web 端现有交互与路由保持不变；桌面端能力通过仅桌面启用的根壳与能力开关接入。
- 首启阶段的必填项只有管理员账号；`sessionSecret`、`desktopKey` 等由主进程自动生成，不得暴露给渲染层。
- 任何可选能力（云同步、Vercel 部署、流量分析、评论验证码）都不得阻塞本地写作与预览。
- 新文案必须同时进入中英文字典；桌面端文案末尾不加句号，Web 端保持 key 对称。
- 提交信息使用英文；代码注释、文档和面向用户的回复使用中文。
- 恢复密钥、同步 Token、管理员密码哈希等秘密不得打印、回显或写入日志。

## 一、现状判断

现有桌面端已经具备可用的基础：Electron 主进程启动本地 Next.js 服务、主窗口不挂 preload、配置保存在 `zlog-config.json`、首启向导覆盖账号与同步、更新与重启链路已跑通。问题不在于「缺功能」，而在于三处体验断层：

1. **首启信息密度过高。** 同步区默认全展开并带三步 Turso 指南，把可选项呈现得像必填项；语言面板在首启被隐藏，非中文用户无法在创建账号前切换语言。
2. **首次登录缺少收尾。** 恢复密钥只能在登录后的设置弹窗中生成，用户很容易跳过；一旦忘记密码且没有恢复密钥，只能手工改库。本轮之前的真实故障就是这一路径。
3. **状态不可见。** 同步是否已配置、是否出错，只在设置窗口可见；后台首页没有「还差什么」的收口，也没有恢复密钥状态的只读接口。

## 二、产品原则（PM/UX 校正后）

- **先能写，再谈云。** 首启完成账号即进入写作；同步、部署、分析都是后置能力。
- **渐进披露。** 首启只呈现必填项和一个折叠的可选项；登录后再用清单补齐恢复密钥与同步。
- **状态先于操作。** 先告诉用户「现在处于什么状态、数据在哪里」，再提供按钮；不把错误藏进设置页。
- **不强制多窗口。** 阅读与写作是同一主窗口的两种模式，避免用户丢失窗口；多窗口只作为后续可选能力。
- **保留 Web 保真路径。** 阅读页不做全量 App 化改造，保留浏览器预览，避免桌面样式与线上文章脱节。
- **可访问性与跨平台从第一阶段纳入。** 键盘可达、焦点可见、减少动效、Windows/macOS 行为一致，不放到最后补。

## 三、目标形态

### 3.1 窗口与导航

- 单一主窗口；启动时恢复上次尺寸与位置，并对超出当前屏幕的坐标做夹取，避免外接显示器拔出后窗口消失。
- 顶部原生菜单 + 窗内工具栏 + 命令面板共用一份命令注册表，保证同一动作只有一处定义。
- 桌面根壳按能力开关渲染；Web 端不加载桌面专属菜单、快捷键和窗口控制。

### 3.2 前台阅读

- 主窗口提供「阅读模式」：更宽的版心、隐藏后台入口、保留返回写作的明确出口。
- 文章页不做强制 App 化，保留「在浏览器中打开」作为保真对照。
- 阅读模式与写作模式共享滚动位置恢复策略，但互不覆盖。

### 3.3 后台写作

- 两栏起步：左侧导航 + 右侧内容；宽屏（≥ 1440px）再提供三栏（导航 / 列表 / 编辑器）。
- 编辑器明确文档语义：标题、未保存标记、自动保存时间、版本入口；关闭窗口前若有未保存修改，必须给出可撤销的确认。
- 列表与编辑器之间保持轻量跳转，不因窗口模式切换丢失草稿。

### 3.4 同步与离线

- 同步状态分为：未配置、已配置且正常、同步中、最近一次失败、云端读取被拒（额度/封禁）。
- 云端不可用时，桌面端继续使用本地副本；状态条明确说明「当前读写的是本地数据」，恢复后提供手动同步入口。
- 首启不要求同步；仪表盘与设置页负责后续补齐。

### 3.5 后台管理

- `SettingsDialog` 继续承担快捷设置；独立设置页承担完整账号与恢复能力。
- 恢复密钥在首次登录后的清单中主动提示，并保留「仅显示一次」的强约束。
- 后台首页顶部提供可关闭的引导清单，完成后不重复打扰。

### 3.6 跨平台与可访问性

- 菜单、快捷键、窗口控制在 macOS 与 Windows 上分别验证；不以单一平台的行为代替另一端。
- 所有图标按钮有可读名称；焦点顺序符合视觉顺序；`prefers-reduced-motion` 下关闭非必要动效。

## 四、首次使用引导（本轮补充）

### 4.1 是否需要引导

需要，但不做一次性长向导。桌面端配置项多，真正的必填项只有一个管理员账号；把同步、部署、分析一次性塞进首启，会放大放弃率。正确做法是三层渐进式引导：

1. **首启最小配置（阻塞）**：语言、管理员账号。保存后立即启动本地服务并进入博客。
2. **首次登录清单（非阻塞）**：管理员账号已就绪、恢复密钥是否配置、云同步是否连接。只把恢复密钥作为可执行项。
3. **情境式提示（按需）**：用户真正打开同步/部署/分析面板时再解释前置条件与故障处理。

### 4.2 首启向导的最小边界

- 必填：用户名、密码、确认密码。
- 可选且默认折叠：Turso 数据库 URL 与 Token，摘要行说明「稍后可在设置中补充」。
- 不在首启出现：Vercel 部署、流量分析、评论验证码、数据目录、关于。
- 语言切换放在品牌头部，中/英二选一，切换后立即重渲染，并写入 `lang.json`。
- 同步字段成对校验：URL 与 Token 必须同时填写或同时留空；校验失败自动展开同步区并聚焦缺失字段。

### 4.3 首次登录清单

- 位置：`/admin/dashboard` 顶部；可关闭，关闭状态写入 `localStorage`。
- 三项状态：
  - 管理员账号：恒为完成。
  - 恢复密钥：通过 `GET /api/auth/recovery` 读取 `{ configured }`；未配置时提供内联生成。
  - 云同步：读取 `/api/sync/status`；未配置时标注「可选」，不提供强制动作。
- 新密钥生成后保持可见，直到用户点击「我已保存」；期间禁止关闭清单。
- 全部基础项完成后标题切换为「基础设置已完成」，但保留清单直到用户主动关闭。

### 4.4 本轮不做

- 不在引导里收集 Turso/Vercel 凭据；这些仍由设置窗口完成。
- 不从主窗口直接打开桌面设置窗口：主窗口不挂 preload 是安全设计，不为引导破坏它。
- 不做跨设备同步的引导状态；`localStorage` 按 origin 隔离，桌面端口变化后清单可能再次出现，可接受。

## 七、验收标准

- 全新安装首次打开：首启窗口出现，语言可切换，语言切换后标题与表单文案立即更新。
- 首启只需填写账号即可保存；同步区默认折叠，留空保存后博客窗口正常打开，`/api/sync/status` 返回 `configured: false`。
- 只填同步 URL 或只填 Token 时无法保存，提示成对填写，并自动展开同步区聚焦缺失字段。
- 登录后台后仪表盘出现引导清单；未配置恢复密钥时可生成，密钥只显示一次，确认保存前清单不可关闭。
- 关闭清单后刷新页面不再出现；恢复密钥已配置时状态为完成。
- `/admin/settings` 可直接生成恢复密钥；设置弹窗行为不回退。
- `pnpm --filter @zlog/desktop test`、`pnpm --filter @zlog/web typecheck`、`pnpm --filter @zlog/web check:i18n` 通过。

## 八、风险与后续

- **恢复密钥丢失**：生成后若用户直接导航离开，明文仍可能丢失。本轮用「禁止关闭清单 + 显式警告」降低概率；后续可在 App Router 层加导航拦截。
- **清单重复出现**：`localStorage` 绑定 origin，桌面端口变化或 Web/桌面双端访问会各自记录。可接受，不做服务端存储。
- **同步状态语义**：`/api/sync/status` 的部分字段是进程内状态，Web 部署下可能没有最近一次同步时间；清单只依赖 `configured` 与 `lastSyncError`，不展示时间。
- **首启语言写入全局偏好**：用户在首启选择的语言会成为整个桌面端的偏好；这是刻意行为，设置中仍可改回「跟随系统」。
