# 主题配色（Base Color + Theme Color）— 设计

日期：2026-10-06 · 状态：已确认，已实施（执行期修订：neutral 块排除 chart-1..5，见 §0.4/§1.3；数据源固定提交号，见 §1.1；2026-10-07 起为上线后修订：基准色板改单轴作用域，见 §3.2；「账号」nav 项固定底部，见 §3.1）

后台设置新增「外观」面板：选择 shadcn **基准色**（经典 5 色）与**主题色**（Default + 精选 7 色）。两轴正交，保存后前端页面与后台系统全部应用。配色目录为官方 registry 快照（入仓，单一事实来源），构建期生成静态 CSS，SSR 直出 `data-*` 属性——零闪烁、零运行时 JS。默认组合（Neutral + Default）与现状视觉一致（图表色例外与处理见 §0.4），零视觉回归。

## Goals

- 后台「外观」面板：5 基准色 × 8 主题色，真实 token 活预览色板，保存后即时生效。
- 前后台所有页面（含登录页、亮/暗双模式）应用所选配色。
- 配色数据 = shadcn 官方 registry 快照 + 生成器 + drift 守护测试。
- i18n 双语（zh/en）+ check-i18n 门禁。

## Non-goals

- 不做任意颜色拾取/RGB 自定义；不做 radius / font / menu accent 等其他 v4 配置轴。
- 不改装饰性硬编码色（清单见 §4）。
- 不做每用户配色（站点级全局设置，与评论/项目开关同层）。
- 不启用官方新版基准色（mauve/olive/mist/taupe）——数据源已备，目录即数据，未来扩展 = 改 JSON + 重跑生成。

## 0. 调研结论（架构依据）

对 shadcn 官方仓库（`shadcn-ui/ui`）与 registry 端点溯源，确认：

1. **官方 v4 就是双轴正交模型**：配置项 `baseColor` × `theme` 两个独立枚举；合并语义为浅合并 `{...base.cssVars, ...theme.cssVars}`（theme 覆盖 base）。证据：`apps/v4/registry/config.ts` 的 `buildRegistryTheme()` 与 `apps/v4/app/(app)/(create)/lib/merge-theme.ts` 的 `buildTheme()`。
2. **accent 主题每模式仅覆盖 11 键**：`primary / primary-foreground / secondary / secondary-foreground / chart-1..5 / sidebar-primary / sidebar-primary-foreground`（`ring` 不被覆盖）。rose 暗色额外含 `sidebar`，原样保真。
3. **数据源**：基准色快照自 shadcn-ui/ui 固定提交 `7ff7dbf8669fa3392c294ee745dc8d8c3cee842c` 的 `apps/v4/public/r/colors/{name}.json`（raw URL）的 `cssVarsV4`（oklch；亮 32 键 / 暗 31 键）；accent 快照自同一提交的 `apps/v4/registry/themes.ts`（抓取日期 2026-10-06）。
4. **默认零回归可证**：现有 `globals.css` 的 `:root`/`.dark` 与官方 neutral 调色**除 `chart-1..5` 外**逐 token 相同（唯一额外 token：自定义 `--login-glow`）。例外：站内图表色为经典彩色调色（与官方 **gray** 基准图表值逐值相同），且 dashboard 真实消费（`country-map`/`contribution-calendar`/`post-stats`/`traffic-analytics` 以 `chart-2` 为特色色）——官方 neutral 的灰阶图表色会改变默认观感，故 neutral 块不发射 chart 键（§1.3）。

## 1. 配色目录

### 1.1 数据文件 — `apps/web/src/lib/theme-catalog.json`（新增）

```json
{
  "source": {
    "commit": "7ff7dbf8669fa3392c294ee745dc8d8c3cee842c",
    "bases": "https://raw.githubusercontent.com/shadcn-ui/ui/7ff7dbf8669fa3392c294ee745dc8d8c3cee842c/apps/v4/public/r/colors/{name}.json (cssVarsV4)",
    "themes": "https://raw.githubusercontent.com/shadcn-ui/ui/7ff7dbf8669fa3392c294ee745dc8d8c3cee842c/apps/v4/registry/themes.ts",
    "fetchedAt": "2026-10-06"
  },
  "bases": {
    "neutral": { "light": { "background": "oklch(1 0 0)", "...": "32 键" }, "dark": { "...": "31 键" } },
    "gray": {}, "zinc": {}, "stone": {}, "slate": {}
  },
  "themes": {
    "blue": { "light": { "primary": "oklch(0.488 0.243 264.376)", "...": "11 键" }, "dark": {} },
    "green": {}, "violet": {}, "rose": {}, "orange": {}, "teal": {}, "amber": {}
  }
}
```

- 值逐字快照，不加工。
- 「Default」不单列：语义 = **不应用 accent 层**（回退基准色自身的 primary/secondary 等，等价官方 mono 主题）。

### 1.2 类型与访问器 — `apps/web/src/lib/theme-catalog.ts`（新增）

- `BASE_COLORS`（5 项，UI 顺序 neutral → gray → zinc → stone → slate）与 `THEME_COLORS`（8 项：default → blue → green → violet → rose → orange → teal → amber），每项 `{ id, label }`，label 用官方英文专名（Neutral/Default/Blue…，不翻译）。
- 类型 `BaseColorName` / `ThemeColorName`（由 `as const` 派生）。
- 常量 `DEFAULT_BASE_COLOR = "neutral"`、`DEFAULT_THEME_COLOR = "default"`。
- 类型守卫 `isBaseColorName(v)` / `isThemeColorName(v)`（DTO 兜底用）。
- ID 数组导出 `BASE_COLOR_IDS` / `THEME_COLOR_IDS`（string[] 形态），API zod 枚举 `z.enum(BASE_COLOR_IDS)` 由数组派生——新增颜色只改目录一处。

### 1.3 生成器 — `apps/web/scripts/generate-theme-css.mjs`（新增）

- 读 `theme-catalog.json`（Node 纯 fs，不依赖 TS），产出 `apps/web/src/app/theme-colors.generated.css`（提交入仓；构建不依赖生成器）。
- 导出纯函数 `generateThemeCss(catalog)` 供测试调用；仅直接运行时写文件（`import.meta.url` 判 main）。
- package.json 加 `"generate:theme": "node scripts/generate-theme-css.mjs"`。

**输出结构与选择器不变式（关键）：**

```css
/* GENERATED by scripts/generate-theme-css.mjs — do not edit. */
/* 基准色段：全部 5 色（neutral 块除 chart-1..5 外与 :root/.dark 逐键等值，见下） */
html[data-base-color="slate"], [data-base-color="slate"] { /* 亮 32 键 */ }
html.dark[data-base-color="slate"], .dark [data-base-color="slate"] { /* 暗 31 键 */ }
/* accent 段：7 色，无 default */
html[data-theme-color="blue"], [data-theme-color="blue"] { /* 亮 11 键 */ }
html.dark[data-theme-color="blue"], .dark [data-theme-color="blue"] { /* 暗 11 键 */ }
```

- **亮色双形态**：`html[…]` 形态特异性 0-1-1 > `:root` 的 0-1-0，**与源码顺序无关地**压过默认值（导入顺序仍是双保险）；裸 `[…]` 形态让面板预览色板可按任意元素作用域生效（非 html 元素上无优先级竞争，变量就近继承取胜）。
- **暗色双形态**：`html.dark[…]` 形态压过 `.dark` 默认块（0-2-1 > 0-1-0）；**`.dark [data-…]` 为后代形态**——任何处于暗色子树内的元素（如暗色模式面板里的预览色板、或显式 `<div class="dark">` 包裹的暗色预览）自动取暗色值，面板内色板随亮暗模式自适应、无需额外 JS。
- **顺序不变式**：基准段整体先于 accent 段（重叠键由 accent 覆盖，复刻官方浅合并方向）；段内亮先暗后。
- **neutral 块照常产出，但排除 `chart-1..5`**：其余键与 `:root`/`.dark` 逐键相等（§5 测试 2 锁定）。**不发射 chart 键的原因**：站内图表色是站点自有调色（`globals.css` 持有、dashboard 真实消费），官方 neutral 的灰阶图表色会改变默认观感、与零回归冲突（§0.4）；预览色板仅用 background/border/primary，不涉图表色，元素级解析不受影响。不跳过 neutral 整块的原因：「外观」面板的预览色板靠**元素级作用域**解析变量——若 neutral 无块，Neutral 选项会继承 ambient html（已保存的其他组合）而非中性值，预览失真。其余 base/accent 块全量发射（官方语义，用户显式选择时生效）。
- **default（主题侧）不产出块**：accent 层「不覆盖」的唯一表达就是无对应块（变量落回基准色自身的 primary/secondary 等）。

### 1.4 引入 — `apps/web/src/app/layout.tsx`

- `import "./globals.css"` 之后 `import "./theme-colors.generated.css"`（按 import 顺序拼接；即便顺序意外反转，`html[…]` 形态仍凭特异性压过 `:root`——双保险）。
- `globals.css` 本体不动。

## 2. 数据链路

### 2.1 DB 列与迁移 — `packages/database/src/site-settings.ts`

- SCHEMA 加两列：`base_color TEXT NOT NULL DEFAULT 'neutral'`、`theme_color TEXT NOT NULL DEFAULT 'default'`。
- `ensureTable` 加两条幂等 ALTER（duplicate column 容错，同 projects_enabled 先例）。
- `SiteSettingsRecord` 加 `baseColor: string` / `themeColor: string`；`rowToRecord` 旧行缺列/NULL → `"neutral"` / `"default"`。
- `upsertSiteSettings`：`baseColor: patch.baseColor ?? existing?.baseColor ?? "neutral"`（theme 同理），并加入 INSERT 列声明 / args / `ON CONFLICT DO UPDATE SET`。
- DB 层类型为 `string`（不 import web 类型）；值域由 API zod 与 `siteConfigFromRow` 双层兜底。

### 2.2 Web 配置层

- `apps/web/src/lib/site-config.ts`：`SiteConfig` 加 `baseColor: BaseColorName` / `themeColor: ThemeColorName`；`defaultSiteConfig` 用 §1.2 默认常量。
- `apps/web/src/lib/get-site-config.ts`：
  - `siteConfigFromRow`：成员校验兜底 `isBaseColorName(row.baseColor) ? row.baseColor : DEFAULT_BASE_COLOR`（防手改 DB 脏值把渲染带崩）；theme 同理。
  - `loadCachedConfig` 显式携带两字段；`getSiteConfig` 加 `?? default` 兜底（跨部署旧缓存条目缺字段，同 commentEnabled 注释先例）；`toSettingsDto` 加两字段（`SiteSettingsDto` 同步）。
- `apps/web/src/app/api/site-settings/route.ts`：`updateSchema` 加 `baseColor: z.enum(BASE_COLOR_IDS).optional()`、`themeColor: z.enum(THEME_COLOR_IDS).optional()`；`dbPatch` 与「首存填默认」分支带上。revalidate 链路已有（`revalidateTag(SITE_CONFIG_TAG, { expire: 0 })` + `revalidatePath("/", "layout")`），无需改动。

### 2.3 SSR 应用 — `apps/web/src/app/layout.tsx`

```tsx
<html
  lang={defaultLocale}
  data-base-color={site.baseColor}
  data-theme-color={site.themeColor}
  ...
>
```

- 始终输出（含默认值）；默认组合中 neutral 块与 `:root` 等值、default 无块 → 渲染与现状一致。
- 前后台共用同一 root layout → 一处生效全局（含 `/admin/*` 与登录页）。
- 属性为服务端常量、html 已有 `suppressHydrationWarning`，无 hydration 风险。

### 3.2 新组件 — `apps/web/src/components/admin/appearance-form.tsx`（新增）

- 独立加载/保存：GET `/api/site-settings` 读当前值；保存 `apiFetch` PUT **仅两字段**（upsert 为局部合并，不会覆盖站点信息字段）；范式仿 `site-info-form.tsx`（含 loading 态）。
- 两组色板：
  - 「基准色」5 项：按钮元素自身挂 `data-base-color="X"`。
  - 「主题色」8 项：按钮自身挂 `data-theme-color="Y"`（default 置首）。
- **真实 token 活预览**（非贴图、非硬编码色值）：
  - 色板内部用 `var(--background) / var(--border) / var(--primary)` 等渲染；基准色板为圆角方块（背景 + 边框 + 中央 `var(--primary)` 圆点），主题色板为圆形填充 `var(--primary)`。
  - **元素级作用域（2026-10-07 修订：基准色板只挂自身轴）**：基准色按钮只挂 `data-base-color="X"`——色块恒为该基准色自身身份（背景 + 边框 + `var(--primary)` 圆点），不随主题色选择变化。原实现两轴同挂（「本选项 × 另一轴」交叉预览），因 accent 段源序在 base 段之后、同特异性下 `--primary` 被当前主题色的 accent 块劫持、圆点随之变色（2026-10-07 用户报告），故移除基准色按钮上的 `data-theme-color`；headless Chrome 对生成 CSS 的级联实测坐实机制与修法（双轴 → blue 主色；单轴 → slate 自身主色），守护测试见 §5。主题色按钮仍双轴：`data-base-color={当前基准} + data-theme-color="Y"`——圆点取本主题 accent（accent 段靠后、同特异性取胜），边框等中性上下文取当前基准色。完全元素级解析、不依赖 ambient html：Neutral 选项落到与 `:root` 等值的 neutral 块、Default 选项无 accent 块 → 显示该基准色自身主色。亮暗随面板所处模式自适应（`.dark […]` 后代形态）。
- 选中态：`ring-2 ring-ring` + Check 图标；hover 态边框/缩放微反馈。
- 保存成功：toast（复用或新增 `appearanceSaved`，实施时核对现有键）→ `router.refresh()`（根布局重渲染 → html 属性更新 → 全站即时换色）。**实施时实测该路径；若 html 属性不随 refresh 更新，回退 `window.location.reload()`**。失败路径 toast.error（同既有范式）。
- 面板内一行说明文案（`appearanceHint`）：配色应用于前台与后台；线上 Pages 静态镜像需下一次构建生效（与总开关同语义）。

## 4. 边界与例外

- **生效时机**：Vercel 运行时保存即生效（revalidate + refresh）；GitHub Pages 静态镜像为构建期烘焙，随下一次 CI 构建生效（与总开关/评论开关同语义，面板文案已说明）。
- **旧缓存条目**（跨部署 Data Cache 缺字段）：`?? default` 兜底。
- **手工改库脏值**：`siteConfigFromRow` 成员校验兜底回默认。
- **chart-1..5**：accent 覆盖图表色（官方语义）——站内 dashboard 有真实消费，该覆盖仅在用户显式选择 accent 时发生（预期行为）；base 侧仅 neutral 不发射图表键（§1.3），其余 base 按官方全量（均为用户显式选择）。
- **装饰性硬编码色**（有意排除）：`hero-section` conic-gradient、`project-cover`、`share-card-dialog` canvas、`comment-avatar`、`mermaid`、admin dashboard tiles、`theme-toggle` 的 `text-indigo-400`、自定义 `--login-glow`。
- **目录扩展路径**：加色/换目录 = 改 `theme-catalog.json` + 重跑 `pnpm --filter web generate:theme`。
